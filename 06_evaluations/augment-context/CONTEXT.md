# Augment point-of-use context walk

This is a synthetic reading evaluation, not a customer record, retrieval engine or executed Run. Start at the [repository router](../../CONTEXT.md) and follow the ordinary Build route. Do not open [EXPECTED.md](EXPECTED.md) until the answers are complete.

For each case, state:

1. the minimum context, recipient and intended use;
2. whether to reuse and route, acquire, or create derived context;
3. source/provider, subject or key, scope, revision or validity time, trigger, required control and point-of-use destination;
4. what remains `open`, which dependent use is blocked and which independent preparation may continue;
5. the execution contribution and any authority or external-effect boundary.

## Cases

| Case | Synthetic premises |
|---|---|
| Current treasury rate | A pricing calculation needs the EUR/USD rate valid for the offer date. The treasury portal provides an approved dated rate by currency pair; direct read access is permitted. The current process asks Treasury by email. |
| Tacit exception | A case worker reports an exception used for ten years. It appears in no maintained rule source. The worker may explain observed practice but has no evidenced rule-change authority. |
| Missing delivery input | A delivery calculation lacks current capacity for one constrained line. No approved fallback exists. A model can estimate from old cases. |
| Decision summary | An authorized manager needs five cited facts, the applicable rule and two open conflicts before deciding. The underlying sources are available and permitted; the manager's authority cannot be delegated. |
| Conflicting revisions | Two reachable procedure files prescribe different thresholds. Their scopes overlap and no precedence decision is recorded. |
| Whole-repository prompt | An agent could technically load 4,000 files. The workstep needs one customer request, the applicable price rule, two exceptions and an offer blank. |
| Late context | The correct approved rate arrives after the offer commitment was made. The rate was current for the offer date and its provenance is intact. |
| Stale price rule | A locally cached price list has a valid digest but expired yesterday. The maintained source exposes a current revision and the workstep declares refresh on expiry. |
| Prior-step handoff | A checked technical finding from the previous workstep is required by the next decision. The producer has a visible output, route and handoff mapping. |
| Shared source, two recipients | A human reviewer needs a short cited comparison; an agent needs the structured rows behind it. Both uses depend on the same maintained source revision. |
| Wrong scope | A checked annual group average is available. The decision requires a current plant-level daily value. Units happen to match. |
| Independent preparation | One decisive approval is missing, while the permitted evidence table and draft decision question can be prepared without it. |

Write the result before opening [EXPECTED.md](EXPECTED.md). A correct answer distinguishes source facts from derived context, design from live availability and context sufficiency from execution permission.
