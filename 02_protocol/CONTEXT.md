# Protocol routing

Owns: routing to each protocol authority, the five static schemas, the templates and the [architect skill](impacts-architect/SKILL.md). Reader: everyone. Does not own: protocol meaning, see [ontology.md](ontology.md).

Each protocol file's reader line names an author, who writes or changes definitions and domain meaning, the harness, which is whoever runs a Vorgang (configured software or an agent session with its human), or everyone, meaning both.

## Entry points

**Before capturing or changing domain meaning, read [Author or change](ontology.md#author-or-change); before applying it, read [Use](ontology.md#use).** [ontology.md](ontology.md) owns protocol vocabulary and scoped obligations. Capability contracts belong to [capabilities.md](capabilities.md); universal source binding and execution belong to [binding.md](binding.md). For customer-facing work, apply [language.md](language.md).

Use [impacts-method.md](impacts-method.md) for the build method; use its [templates](templates/) and [layout rules](binding.md#hauptprozess-tree-rules) only when constructing or changing a Hauptprozess. For customer initialization or knowledge topology, use the [Architect's form selection](impacts-architect/SKILL.md#form-selection). Customer files own meaning and evidence; this router only selects the next authority.

## Task routes

For source-grounded answers, apply the [Use completion check](ontology.md#use). Select one row, then load its Start and only the conditional targets whose named condition applies; when access permits, read that bounded set together. Each fact keeps its existing home.

Instruction maintenance starts at [Maintain agent instructions](impacts-method.md#maintain-agent-instructions). Existing route use or diagnosis starts at [Load context locally first](impacts-method.md#load-context-locally-first), including a copied or projected bundle, missing delivered material and a context-efficiency claim. A mixed task maintains the instruction first, then exercises the route.
