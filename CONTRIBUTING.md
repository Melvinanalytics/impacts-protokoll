# Contributing

Changes enter `main` through a reviewed pull request. Keep customer material in its customer repository. Report the revision, expected and observed behavior, synthetic evidence, and checks not run.

### v0.9.0

This minor edition adds upgrade-preview and protocol-citation validation flags, extends the 24,000-byte router ceiling to `Arbeitsschritt` bodies, exposes a public single-Vorgang JSON/Python read API, clarifies process/project variance and the communication capture filter, and upgrades the read-only HTML Human view (`impacts view`) with Level-0 system/market-topology docking, legacy Vorgang read projections, attempt output previews, recursive `analyse/`/`bridge.md` discovery and multi-library `Stage:`/`Stufe:` support. Workspaces pinned to `v0.8.x` remain `not_judged` until they lift their pin to `v0.9.0`; preview the lift safely with `--preview-pin`. Schemas, required fields, issue codes and folder forms are unchanged; the JSON report gains `preview_pin` under `report_version: 3`.

- **Read-only pin-lift preview (`--preview-pin`):** `impacts validate PATH --preview-pin` judges a workspace pinned to another release line as if its root `protocol:` matched the running release, without modifying files (`pin` keeps the recorded value, `workspace_judged` and `preview_pin` become true, and older Vorgänge remain `not_judged`). Combining `--preview-pin` with `--require-judged` exits 2 so a commit gate never mistakes a preview for a pinned workspace.
- **Protocol code-span verification (`--protocol-source DIR`):** `impacts validate PATH --protocol-source DIR` verifies `` `02_protocol/<path>#<anchor>` `` code spans in checked routers and definition bodies against `DIR/02_protocol/` (rejecting symlinks and `..` escapes) and reports unresolved paths or anchors as `topology.link_broken`.
- **`Arbeitsschritt` router size ceiling:** `topology.router_size` (navigation family, never refuses a Vorgang page) now measures `type: arbeitsschritt` `CONTEXT.md` files under `hauptprozesse/` against the 24,000-byte Knowledge Walk budget, advising movement of detail into linked sibling files or referenced foundations ([Router size and table contracts](02_protocol/impacts-architect/references/formwahl.md#router-size-and-table-contracts)).
- **Public single-Vorgang status API:** `impacts view <source> --json-stdout` prints the read-only view JSON model without creating an output folder, and `impacts_protocol.view.vorgang_model(path)` exposes the stable in-process single-Vorgang model alongside `site_model`.
- **Human view (`impacts view`) upgrades and normative specification:** [Human view](02_protocol/impacts-method.md#human-view) (routed from [02_protocol/CONTEXT.md](02_protocol/CONTEXT.md#task-routes)) defines the viewer's purpose, lifecycle checkpoints, stable `a-<slug>.html` naming for valid Hauptprozess slugs and boundaries. The viewer now supports `View: <relative-path> [| <title>]` in root `CONTEXT.md` to dock domain HTML or Markdown system/market-topology views as Level-0 (`s-*.html`) linked from `index.html`; renders a clearly bannered unjudged legacy read projection (`legacy`) for `not_judged` Vorgänge under [Snapshot and provenance](02_protocol/binding.md#snapshot-and-provenance); discovers nested `type: ist-prozess` and `bridge.md` files inside `analyse/` case subfolders (keeping candidate Hauptprozess trees and empty folders skipped); scans all declared top-level `Record Library` folders and recognizes German `Stufe:` alongside `Stage:`; attaches bounded text previews for `geschrieben` outputs and open-attempt drafts (`draft: true`) in Vorgang timelines; collapses empty overview blocks and the schema `Datenmodell` table; and adds standalone SVG export with embedded `<style>` and resolved color tokens on process maps.
- **Process/project variance and communication capture filter:** [Process and project variance](02_protocol/impacts-architect/references/formwahl.md#process-and-project-variance) contrasts low-variance Pipelines with high-variance projects backed by a `Record` backbone plus plug-in Pipelines; [Capture filter for unstructured communication](02_protocol/impacts-architect/references/formwahl.md#capture-filter-for-unstructured-communication) (cross-referenced from [datenumgang.md](02_protocol/impacts-architect/references/datenumgang.md#business-data-at-a-glance)) defines the three-way filter from the `Leistung` backwards (discard chatter, condense settled choices into `Decision record` + subject record, keep binding outside documents as `Received source`).

Conformance: the runner requires and validates `preview_pin` (`false` without `--preview-pin`) under `report_version: 3`; frozen corpus lifted to `v0.9.0` (`run-newer-than-pin` to `v0.10.0`).
Moved anchors: none. Retired terms: none.

### v0.8.1

This patch edition makes the data-handling contract consistent and readable for companies without a data department. Schemas, required fields, issue codes, validator rules and CLI commands are unchanged; `v0.8.0` pins remain judged.

- **One term for the authoritative system:** `system of record` (German *führendes System*) is defined once in [Source descriptions](02_protocol/impacts-architect/references/datenumgang.md#source-descriptions) and replaces seven earlier names; `tests/retired_names.md` blocks the old ones.
- **Personal data default:** [Retention and deletion](02_protocol/binding.md#retention-and-deletion) replaces the absolute ban on personal data in Git with three classes: no personal data; people in a professional role, allowed in a private workspace with the fewest needed fields; private or sensitive data, kept in the company's system of record or an external `ablage` with a store-keyed digest. Legal basis, retention and deletion stay with the company's data-protection governance. The Subject record examples no longer list addresses or candidate status.
- **Consistent homes:** the ERP and planning example captures moved from `records/` to `vorgaenge/<vorgang>/_quellen/` with provenance files; a local copy of a subject record needs a confirmed storage gap; a population row becomes a subject record at the first decision about it alone; `as-of` wording now names the [clock](02_protocol/ontology.md#domain-addresses-and-relationships) it means; the scope line of `binding.md` covers writeback, promotion and retention in ordinary work.
- **Readable entry:** [Business data at a glance](02_protocol/impacts-architect/references/datenumgang.md#business-data-at-a-glance) answers where a fact comes from, where meaning and rule live, where a calculation runs and what the workspace keeps, and maps data management, business intelligence and data science to these homes. A three-step delivery-time example shows the flow without a second table to maintain. `02_protocol/CONTEXT.md` gains a task row for business data.
- **Two lifecycle cases:** a record deleted in its system of record leaves its value `open`; a changed source ID goes into the key mapping with its validity period.

Migration: none required. A workspace that keeps private or sensitive personal data in Git should move it under its own governance; the protocol does not rewrite history. Moved anchors: none. Retired terms: seven synonyms of `system of record` (listed in `tests/retired_names.md`). Limits: a cold-reader test ran with agents, not with a company reader; the store-keyed digest is a harness duty that `impacts validate` cannot check.

### v0.8.0

This minor edition splits topology findings into structure and navigation codes and adds four router checks. Workspaces pinned to `v0.7.x` are reported as `not_judged` until they lift their pin to `v0.8.0`; rehearse the lift on a copy, since the new findings appear only on the new line. Schemas, required fields, CLI commands and folder forms are unchanged; `impacts validate` gains one flag and the JSON report one field.

- **Navigation codes split from structure:** `topology.shape`, `topology.form_missing` and `topology.form_invalid` keep structure and readability findings: an unreadable entry, a definition outside `hauptprozesse/`, a loose file or a process folder without router in a process home, mixed Record Library shapes. Link findings move to `topology.link_missing` (an entry, level or root file its router does not link, or a level without its router) and `topology.link_broken` (a link or `#anchor` that does not resolve, points to a path Git ignores, is absolute, leaves the workspace or is misspelt). The Viewer refuses a Vorgang page only for structure findings outside the two Core folders, never for navigation or router-shape findings, and the exported `superseded` relation follows the same rule through one shared helper. A navigation finding inside a Hauptprozess folder shows on that Hauptprozess page as a note, on the workspace site only: `impacts view hauptprozesse/<slug>` does not validate the workspace and carries no notes. [Finding codes](02_protocol/impacts-architect/references/formwahl.md#finding-codes) lists each code with its family.
- **Level router sections:** every Record Library, Knowledge Bundle and Context Map router holds the headings `Overview` and `What to load` (German `Übersicht`, `Was laden`; letter case ignored), as `impacts template ebene` lays them out; otherwise `topology.router_sections`. Sections, anchors and table-contract headings share one heading reading: up to three spaces of indent, backticks and link markup in the title do not matter. This holds at any entry count, so a tool that adds an entry never turns a workspace red. A regular `README.md` beside a level's instance folders is no record entry.
- **Links in definitions:** relative links and `#anchors` in Hauptprozess, Teilprozess and Arbeitsschritt bodies under `hauptprozesse/` must resolve inside the workspace (`topology.link_broken`). Folders starting with `_` or `.` are skipped.
- **Router size:** the root router, each Knowledge Bundle router and each Capability, Tool or Check router (the home's `CONTEXT.md` and each direct entry's) stays at or below 24,000 bytes, three quarters of the 8,000-token Knowledge Walk budget at about 4 bytes per token; otherwise `topology.router_size`. The limit is derived from that budget, not measured on a reader. The finding says how each form shrinks: root and code routers move detail into linked sibling files; a Knowledge Bundle, whose router must link each entry, splits into declared sub-levels. Record Library and Context Map routers are exempt, since they must link every entry: a Record Library kind that outgrows the limit splits into period sub-levels, and a Context Map has no sub-levels at all. Definition and Vorgang files are not measured.
- **Table contracts:** an opt-in comment `<!-- impacts:table-contract heading="<Heading>" columns="<Col1>, <Col2>" -->` in a router declares a table a tool writes rows into; the heading and every named header column must exist in every section with that heading, outside HTML comments (`topology.table_contract`). The attributes may come in either order, the heading matches in any letter case, and the comment is read in every router the validator reads, Pipeline homes, process folders and definition bodies included. Without the comment nothing is checked.
- **Unindexed folder links:** a root or level router link to a folder other than its own entries that has neither `CONTEXT.md` nor `README.md` (exact spelling) is `topology.link_unindexed`. Code homes, held folders, declared levels, whose own rules govern them, and the Core folders `hauptprozesse/` and `vorgaenge/` are exempt.
- **Record names no longer judge a Knowledge Bundle:** a Knowledge Bundle entry with the name of a record instance is no longer `topology.shape`. A name says nothing about what a file holds, and the finding tied a valid bundle to the growth of a Record Library: a second record file, or a new instance with the same name, made an unchanged bundle entry fail. Dated and undeclared entries stay findings. A level entry that is a symlink counts as linked only by a link to itself, not by one to its target.
- **Templates:** the Arbeitsschritt template gains a "Tool sequence" subsection with recovery paths in a linked side file; the level router template gains a "Call and checks" block for code routers and an optional contract line; the workspace template sends pure read questions straight to the read table.
- **Predecessor reading:** a successor reads the Arbeitsschritte of its predecessor's bound tree with the same line-wise frontmatter rule as validation, so `---` inside a frontmatter value no longer breaks or cuts short the route lookup. Files in that tree that do not parse are skipped, since only the predecessor's position is read; an unreadable matching Arbeitsschritt still leaves the route unresolved. The tree is read through the Git process of committed reads below, once per tree and run: on a synthetic chain of 100 successors over a 32-step tree, a run took 28 s with 3,410 Git processes and now takes 0.6 s with 10.
- **Succession across releases:** a judged Vorgang that names a `vorgaenger` already named by a not-judged Vorgang is rejected with `execution.attempt`. Before, lifting the pin let a new Vorgang fork one that an older Vorgang already continued. The not-judged successor still supersedes nothing.
- **Paths Git ignores:** the topology check reads the workspace as a clean clone would. A link to a path Git ignores is `topology.link_broken` where it is written, with a message saying Git ignores it; a router or `README.md` Git ignores counts as absent, so a level router is `topology.link_missing`, a process router `topology.shape` and a folder index `topology.link_unindexed`. Before, such a workspace passed on the author's machine and failed on every clean clone. For these paths, codes and paths match on both; only the local message says why. Core's reference and output checks still read the working tree, so an attempt output Git ignores passes locally and fails on a clone; `binding.md` says not to ignore paths under `vorgaenge/`.
- **Committed reads:** `impacts validate` reads every `gelesen` reference with a `git-commit:` revision through one Git process per run and reads each tree and file once, where it used to start three processes per reference. On a synthetic workspace with 200 Vorgänge of 25 such references each, a run took 115 s and now takes 1 s; `impacts view` was slow for the same reason. Finding codes and exit codes are unchanged; one message changes: a 40-hex revision in a SHA-256 repository now reads "Reference commit is missing" instead of "unreachable", since no commit has that id.
- **Judged gate:** `impacts validate --require-judged` exits 1 when the workspace pin names another major.minor than the core, so a commit hook that passes it fails on a workspace nothing checked. Before, such a run exited 0 with no issues even on a broken workspace, and a hook that read only the exit code went blind after an unnoticed core upgrade. Without the flag that run still exits 0. The JSON report gains `workspace_judged` under `report_version: 3`, as `judged` and `held` did; the conformance runner requires it and checks it against the root `not_judged` entry. Not-judged Vorgänge and definition trees in a judged workspace do not trip the flag, since a Vorgang keeps its recorded release after every lift.
- **Method text:** `impacts-method.md` describes an ongoing update to a new source revision; `formwahl.md` names files that stay in a source repository as `<repo>:<path>` code spans; `binding.md` gives a `not_judged` Vorgang a read projection labelled as legacy reading; `formwahl.md` allows period sub-levels of a record kind and refuses stage sub-levels; `binding.md` states when a finished Vorgang may leave `vorgaenge/` for Git history; the Necessity sweep runs in a workspace at a size or friction trigger, one area at a time.

Conformance: five frozen cases change their expected code from `topology.shape` to `topology.link_missing` (`topology-root-unlinked-level`, `topology-record-router-missing`, `topology-record-instance-unlinked`, `topology-record-file-router-incomplete`, `topology-pipeline-home-unlinked`); fifteen cases are new, `run-predecessor-dash-value`, `run-predecessor-not-judged-successor`, `topology-record-period-sublevels` and `run-producer-vorgang-removed` among them. The corpus runs `validate` only, so the Vorgang page result of the two Viewer cases is checked in the reference tests. Moved anchors: none. Retired terms: none.

Migration: before pinning `v0.8.0`, move detail out of each Capability, Tool or Check router and the root router above 24,000 bytes into linked sibling files, and split each Knowledge Bundle level whose router passes that size into declared sub-levels; link each symlink entry of a level itself, or remove it; an imported Hauptprozess or Capability tree stays identical to its source tree, so split its routers and repair its definition links in the source repository, and lift the workspace pin only after taking that revision; Record Library and Context Map routers may stay larger; give every level router both headings, `Overview` and `What to load`; repair links in definition bodies, which changes the definition's tree id and so binds new Vorgänge only; give every folder a root or level router links, other than its own entries and declared levels, whether deeper, a sibling level or a parent, a `CONTEXT.md` or `README.md`, or link a file inside it; tools that match on `topology.shape` for link findings now read the two link codes; point a new Vorgang whose `vorgaenger` an older Vorgang already continues at that continuing Vorgang; commit or unlink each linked path Git ignores, a root link to an ignored folder included, and stop ignoring any router; add `--require-judged` to any commit hook or gate that runs `impacts validate`, in the change that adopts the `v0.8.0` core, since older cores reject the flag with exit 2; a JSON reader that checks the exact key set adds `workspace_judged`; a kind already split into stage folders such as `aktiv/` and `abgeschlossen/` gets no finding, but moving an instance between them breaks Subject links, so split by period instead, in one commit that also repoints every Subject link to the moved instances; delete a superseded clearance line in the root router instead of striking it through, since struck lines count toward its 24,000 bytes. Limits: the checks prove that headings, sizes, columns, links and index files exist, not what they say or that a router routes a task well. Renaming or moving a file or `#anchor` that a Hauptprozess definition links turns `impacts validate` red until a new definition revision repairs the link, which means a new tree id and a new clearance line. No fresh-session test in a customer workspace was run for this edition; its effect on agents' reading is not measured. Only ignore rules are read: a link to an untracked file Git would carry passes until a commit leaves it out, and an empty folder, which Git cannot carry, still counts as present, so its finding may differ on a clone. The 24,000-byte bound is a ceiling for one router derived from the 8,000-token Knowledge Walk budget, not measured on a reader, and does not by itself keep a walk under budget. The Markdown reading stays simple: setext headings, reference-style links, links with a `?query` and CR-LF line ends are not fully handled, and a code span stays inside its paragraph but, as in CommonMark, wins over a comment that opens later in that paragraph, so a stray backtick before such a comment exposes the comment's text. Planned, not in this edition: a count of finished Vorgänge and router sizes per area in `impacts validate` or `impacts view` output to trigger the workspace sweep; it needs new output fields.

Grounding: ICM (arXiv 2603.16021, section 3.2) routes each task from Layer 1 and has each stage's Inputs table name exact files; reference collections may carry their own routers. These rules make the router chain checkable and leave per-file navigation to the declared inputs.

- **Fixes:** a misspelt link to a Record Library entry or to a level from the root is reported once, at its spelling; a stray file among instance folders no longer lifts the router duty. Five conformance cases freeze the new rules.

Migration: link each level from the root route that serves its readers; give each Record Library level with sub-levels or instance folders a `CONTEXT.md` that links them; complete partial routers of file kinds; tools that create instance folders write their router row in the same change. Moved anchors: none. Retired terms: none. Limits: the check proves that links exist, not that a route sends a given task to the right level. ## Bounded Linux dependency install

For a fresh virtual environment running CPython 3.11 on Linux x86_64 with glibc 2.17 or newer, the checkout includes a hash-enforced install recipe:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python .github/scripts/install_runtime.py
```

Run it from the complete checkout. It checks the interpreter, architecture, libc and virtual environment; installs binary dependencies from the PyPI index with `--require-hashes`; then installs this checkout editable without resolving dependencies again. Record the checkout's Git commit. The lock binds selected wheel bytes for this target. It does not bind Python, pip, the checkout's authenticity, build provenance or package publishers. It makes no dependency-closure claim for other Python versions, operating systems, architectures or libc versions.

## Publish an edition

An edition claim spans source text and public delivery. `pyproject.toml`, the annotated Git tag, GitHub Release, release assets, README URLs and filenames, and installed package metadata must name the same version. A green documentation test establishes only the source-tree part. For descriptive file-count scale checks, run [benchmark_scale.py](tests/benchmark_scale.py).

Run the complete repository checks in the clean public candidate tree. A source checkout with additional private directories is not that release surface; prepare the complete allowlisted export first rather than raising the budget or suppressing failures. Retain the candidate tree identity and check the actual predecessor selected by the complexity gate against the intended prior release. An uncommitted tree check does not establish the later release commit or its ancestry.

Use this order:

1. Create `release/vX.Y.Z` from current public `main`.
2. Change `[project].version` plus all release URLs, clone commands, wheel filenames and edition wording in `README.md`. Regenerate affected template translation hashes.
3. Run the complete repository checks. Open and review the release pull request. Do not create a public Release from an unmerged branch.
4. Merge the reviewed release commit. Create an **annotated** `vX.Y.Z` tag on that exact public `main` commit and push the tag once.
5. The tag workflow uses a read-only build job to check the tag, source claims and full test suite on Python 3.11 and 3.14; build the wheel and complete source archive on Python 3.11; and write `SHA256SUMS`. A separate publish job downloads those checked bytes without installing or running package code, uploads exactly the three artifacts to a hidden draft Release, verifies their remote names and SHA-256 digests, and attaches compact test evidence to the draft body before publication by numeric ID. Evidence must match the source and workflow run, with both interpreters from the same build attempt. Retrying only publication may reuse that successful earlier build attempt. The publicly readable body labels JUnit counts including subtests as workflow evidence, not independent verification or attestation.
6. Verify that `main`, `vX.Y.Z`, the Release and its assets resolve to the intended commit and bytes. Run the optional live check below.

For an initially unpublished version, a failure before the final publish command leaves the Release absent or draft. A rerun rejects an already published Release without modifying it. Repair a published edition through a new reviewed commit and version; do not move a published version tag or replace assets on a published Release. A manual rerun accepts only an existing annotated tag and may repair an unpublished draft.

Recovery depends on which source is wrong:

- If the workflow itself fails while the tagged source remains correct, repair the workflow through a normal pull request to `main`, then run `workflow_dispatch` from `main` for the same existing annotated tag. The publish job may reuse exactly one unpublished draft for that tag.
- If the tagged source is wrong, do not move or replace the tag and do not create a Release manually. Leave or discard the unpublished draft and correct the source in a new edition such as `vX.Y.(Z+1)`.

The workflow makes the draft-to-public Release boundary fail closed: it publishes only after the uploaded artifact names and digests pass. The preceding merge and tag push are separate public writes and cannot form one transaction with GitHub Release publication. Do not call the edition released until `main`, tag, Release, assets and public verification agree. Verify that public state separately after the workflow succeeds.

```bash
IMPACTS_LIVE_RELEASE_CHECK=1 python -m pytest -q \
  tests/test_public_release.py::test_live_current_release_contains_required_assets
```

That optional test checks the presence of the named assets. To verify their exact names and bytes, download them and run `release_guard.py live --tag vX.Y.Z --dist <download-directory>`.

An edition does not identify a consumer's bound revision. Customer repositories continue to record the exact commit or verified archive they use.

Do not delete or rewrite existing version tags or Releases without an explicit human decision.
